修炼存档

修炼存档让你在一个账号上最多保留三名各自独立的修士，并随时自由切换。想从炼体重新起步，不必舍弃你花了一个月修成的元婴 —— 想回去时随时回去。v0.7.0 新增。

无需任何设置：你现在的修士会在你第一次查看时自动成为存档 1。

存档随身携带什么

存档承载的是*你是谁*，而非*你拥有什么*。切换改变的是修士本身；凡是系于账号或系于世界的，一概原地不动。

随存档转换归于账号
境界、阶段与灵气你的宗门与门中职务
种族你的洞府与其灵泉
大道 —— 元素、道途、阴阳与业力你掌控的阵法
天赋树道侣，及双修
已习得的功法及其键位方案设置 —— HUD 各行、气息开关、佩戴的称号
生效中的丹药效果你的背包，以及 Hytale 本身所辖的一切

道理在此：宗门里有其他成员，山门可被他宗围攻；洞府是已占之地。这些是世界的事实，无法随一份存档而去。佩戴的称号留在账号上，常令人意外 —— 称号是账号的装点，并非修为本身。

切换同时会清除进行中的仪式，而非将其带走 —— 一场突破绝不会留在一名已然不在的修士身上继续进行。

管理存档

打开菜单栏上的存档页 —— 它就在设置旁边 —— 或使用 /cultivation profile：

指令
指令作用
/cultivation profile列出你的存档及其境界、阶段与灵气，并标明当前所在
/cultivation profile new confirm封存当前修为，从炼体从头再来。仅在传入 confirm 一词时生效
/cultivation profile switch {编号或名称}保存当前修士并接续那一份存档
/cultivation profile rename {名称}重命名当前存档（上限 24 字符）
/cultivation profile delete {编号或名称}将那份存档永久抹去

两项毁灭性操作都会先行确认。在菜单上，抹去与重新起步第一次点击进入待确认态、第二次点击才会执行 —— 点击任何其他地方即解除。抹去会拒绝你正在修炼的存档与你仅剩的最后一份，因此账号永远无法把自己删到一无所有。

每次切换前、以及断线时，进度都会写入存档。这里没有任何东西在后台运转 —— 你不在的存档只是一份静止的记录。

存档上限

默认三份。该上限并非配置项：扩展模组可通过 API（registerProfileCap）提高它，硬性天花板为六份。若提高上限的扩展后来被移除，你已填满的每一份存档都会保留 —— 只是在回到上限以下之前，不能再*新建*而已。

何时无法切换

若有模组接管了 Cultivation 的修为体系（即 ProgressionProvider，例如为服务器另设一套等级的扩展），它必须明确声明自己的记录会随你的存档同步。在它声明之前，切换会被直接拒绝，而非做一半 —— 提示会说明本服的修为由其他模组掌管。这是刻意的保护，不是故障 —— 若你维护这样的模组，见编写扩展。

试炼存档

写给服主：持有 cultivation.profile.test 权限者可获得一具额外的临时修士 —— 一个沙盒，其境界、阶段、灵气、天赋点与种族皆可亲手设定，用于试验平衡改动而不动真身。它不占用你的三个存档位。

指令
指令作用
/cultivation profile test {时限}进入（或延长）试炼之身。时限必填 —— 30m、4h、2d，或纯数字视为分钟；范围 1 分钟至 30 天
/cultivation profile realm {境界}按枚举名设定境界，如 VOID_REFINEMENT
/cultivation profile stage {阶段}EARLY、MIDDLE、LATE 或 PEAK
/cultivation profile qi {数值}设定所积灵气
/cultivation profile points {数值}设定（而非增加）可用天赋点
/cultivation profile race {种族}设定种族，绕过境界门槛
/cultivation profile reset将试炼之身抹回一名全新修士，而不离开它

同样的控件也在存档页的试炼存档一节里，时限预设自 15 分钟至 7 天。

三条性质使它可以放心授予：

  • 它会自行消散。时限按真实时间计算，下线也无法拖延。时限一到，你被送回自己的第一份真实存档，试炼之身随即弃置，不作保存。
  • 它无法上榜。试炼修士不入排行、不计宗门积分、不上宗门名册 —— 打字打出来的境界，绝不该压过修出来的境界。你最后一次*真实*的名次会留在榜上。
  • 它在进度扩展之下也可用 —— 这是唯一被放行的存档操作 —— 但该扩展看到的仍是你的真实等级，指令也会如此说明。

写给服主

存档刻意没有任何配置项：没有开关能关掉它，上限也只经 API 变动。唯一的运维面是 cultivation.profile.test 权限 —— 默认不授予任何人。见权限。

对扩展作者而言，ProfileEvents 携带七个事件（切换、创建、抹除、到期），前三者各有可取消的前置事件。
