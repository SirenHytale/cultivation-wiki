# xianxia.dev — Cultivation Wiki

The documentation site for **[Cultivation](https://www.curseforge.com/hytale/mods/cultivation/)**, a
Xianxia realm-and-Qi progression mod for Hytale.

**Live at [xianxia.dev](https://xianxia.dev)** · 53 pages, bilingual (English + 简体中文) ·
Next.js 16 · deployed on Vercel

## The whole site is `web/`

```bash
cd web
npm install
npm run dev      # http://localhost:3000
```

Node 20.9+ (Next 16 requires it). Everything — pages, chrome, styling, the two interactive
tools, the live `/api/get/**` endpoints — lives under `web/`. The repo root holds only this
README and the agent rules.

| Path | What it is |
| --- | --- |
| `web/content/en/`, `web/content/zh/` | Every page, one MDX file per slug |
| `web/lib/nav.ts` | Navigation — the single source of truth for the top bar and sidebar |
| `web/app/(en)/`, `web/app/(zh)/` | The two root layouts (see below) |
| `web/components/mdx/` | The theme components MDX uses: `<Note>`, `<Card>`, `<Panel>`, `<Divider/>`… |
| `web/components/chrome/` | Header, sidebar, TOC, footer, search |
| `web/styles/` | `xianxia.css` (the theme) + `next-overrides.css` (put changes here) |
| `web/public/api/get/` | **Live JSON endpoints** deployed mods poll for update/compat checks |
| `web/tools/` | Local generators — diagrams, skill-tree data, social card, SVG art |

`web/README.md` is the architecture document. Read it before changing anything structural.

## Adding to the site

Add a page:

1. `web/content/en/<slug>.mdx` (and `web/content/zh/<slug>.mdx` if it is translated)
2. An entry in `web/lib/nav.ts` — without it the page renders but is unreachable
3. `cd web && npm run diagrams` if you added a Mermaid fence

Nothing else regenerates. The search index, sitemap, breadcrumbs, prev/next links and social
metadata all derive from the MDX and `lib/nav.ts` at build time.

**Never author HTML.** See `AGENTS.md` — the rule and the reasoning are there.

### The local generators

Run from `web/`. None of them are part of `next build`; they need Python or a browser, and
Vercel builds stay free of both. Commit their output.

| Command | Does |
| --- | --- |
| `npm run diagrams` | Pre-renders every ```` ```mermaid ```` fence to SVG in **both** themes → `lib/data/diagrams.json`. Keeps the diagram renderer out of the browser entirely. Needs headless Edge. |
| `npm run skilltree` | Regenerates `lib/data/skilltree.json` from the mod's `SkillTreeRegistry`. Only when the mod's tree changes. |
| `npm run card` | Renders `tools/card.html` to the 1200×630 `social-card.png` via headless Edge. |
| `npm run art` | Regenerates the bagua seal, ink divider and favicon SVGs. |

## Why the URLs look the way they do

English pages serve at the root (`/dao/`), Chinese mirrors them under `/zh/` (`/zh/dao/`).
No `/en` prefix, and `trailingSlash: true` — so every link, bookmark and search result from
the site's static-HTML era still resolves.

That is why there are **two root layouts** rather than one `[lang]` segment: a single layout
cannot vary `<html lang>` per language without opting every page out of static generation.
Next resolves the static `zh` segment ahead of the English `[slug]`, so they do not collide.

## Things that will break the site if forgotten

- **`/api/get/**.json` is a live endpoint.** Deployed Cultivation, JadeSlip, SoulRings and
  SacredBodies clients poll it. Files live in `web/public/api/get/`. **Never put a route
  handler under `/api`.** (The site's own search is at `/wiki-search/` for this reason —
  and must be fetched *with* the trailing slash, or it costs a 308 per keystroke.)
- **Pinned MDX anchors must stay escaped**: `## Heading \{#anchor\}`. A bare `{` is lexed as
  a JSX expression and fails the parse before any plugin runs.
- **`styles/xianxia.css` is the inherited theme** and is kept as-is so its tokens stay
  legible. Framework-specific changes belong in `styles/next-overrides.css`.

## Deploying

Vercel project `SirenHytale/xianxia.dev` with **Root Directory** set to `web`. Push to `main`
deploys. After any deploy, spot-check `/api/get/version/cultivation.json` — mods depend on it.

## History

Until 2026-08-04 this repo also carried the original site: zero-build static HTML at the repo
root, generated by Python scripts in `tools/`, served by GitHub Pages. Every page had to be
maintained twice once the Next.js port landed. The static tree, its generators and its
Markdown sources are deleted; they are in git history and on the `before-nextjs` branch.
