Read API

Static, read-only JSON served straight from this site. No keys, no rate limits, no write endpoints.

Version manifests

Each mod in the Cultivation family publishes the version it considers current. The mods fetch their own manifest to tell a server owner when an update is out. Build digests are published alongside them.

ModEndpoint
Cultivation/api/get/version/cultivation.json
Cultivation: Jade Slip/api/get/version/JadeSlip.json
Soul Rings/api/get/version/SoulRings.json

Shape

{
  "release": "0.7.1",
  "ignore": ["0.7.0"]
}
FieldTypeMeaning
release string The current version. A server running anything older than this has an update available.
ignore string[] Installed versions that are never notified, even when they are behind release. Use it to spare a build that should sit where it is — a beta, or a version whose upgrade path is not ready yet.

How a mod reads it

  • Fetches its manifest on a background thread at boot, then on an interval.
  • Stays silent when the installed version equals or exceeds release, when the installed version appears in ignore, or when the request fails for any reason.
  • Otherwise tells server administrators, once, as they join.
Both fields are optional to consume: a missing or unparseable manifest is treated as “no update”, never as an error a player sees. Version strings compare numerically part by part (0.10.0 is newer than 0.9.0).

Build digests

Each mod also publishes a digest of the compiled code in every official release. A running mod hashes its own jar the same way and compares, which lets it tell the jar that shipped from one that was rebuilt.

ModEndpoint
Cultivation/api/get/build/cultivation.json
Cultivation: Jade Slip/api/get/build/JadeSlip.json
Soul Rings/api/get/build/SoulRings.json
 
{
  "builds": {
    "0.7.1": ["f1ad9b61...49146cc5"],
    "0.7.0": ["71bd0e42...9c110a04", "5e9033f1...b7d2e880"]
  }
}

Keyed by version, each holding the digests accepted as official for it — an array, so a version legitimately rebuilt more than once can carry more than one. The digest is SHA-256 over every .class entry in the jar, in name order, each contributed as its name, a NUL, its length as four big-endian bytes, then its bytes. Resources are not included: the question is whether the code was rebuilt, so editing a language file inside a jar does not make it unofficial.

A version absent from builds leaves that install unverified, not condemned — as does an unreachable endpoint or an unreadable jar. A mod only concludes it is unofficial on a positive mismatch: digests were published for its exact version and its own was not among them.

This is detection, not protection. Anyone able to rebuild a mod is equally able to remove the check, and no code running on someone else’s machine can do better. What it reliably catches is repackaged uploads, redistributed paid addons, and downloads that arrived damaged.
