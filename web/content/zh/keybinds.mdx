# 快捷键与配置组

施展功法不必再敲指令。将功法绑到**修饰键加主键**上，按键即发。此功能于 v0.6.0 加入，默认开启（`Technique-Hotkeys-Enabled`）。

在任意修真菜单的**快捷键**页设置，或以 `/cultivation debug hotkeys` 查看当前绑定。

<Divider />

## 服务端如何「看见」按键

这一点值得先弄明白，因为下文的每一条限制都由它而来：**Hytale 的通讯协议根本不传键盘输入。**服务端永远不会知道你按了哪个键 —— 只知道按下之后发生了什么。

因此，唯有按下时会产生服务端可见后果的键，才可绑定：

| 按键 | 服务端实际看到的 |
| --- | --- |
| **1** – **9** | 切换快捷栏格位 |
| **Q** | 请求丢出手中物品 |
| **E** | 请求打开背包 |
| **R** | 请求切换快捷栏方块组 |

**没有 0 键**。快捷栏只有九格，按 0 切不到任何格位，服务端也就无从得知。

修饰键同样是间接读到的 —— 通过它们各自驱动的移动状态：

| 修饰键 | 移动状态 |
| --- | --- |
| **ALT** | 行走 |
| **CTRL** | 潜行 |
| **SHIFT** | 疾奔 |

## 是「按下」，不是「按住」

这一条最容易踩空。修饰键是由**按下**这一下所触发的，而非按住：窗口在你按下的那一刻开启，**半秒之后关闭**，与你是否仍按着无关。

- 轻点 **ALT**，半秒内再按 **6** —— 触发。
- 按住 **ALT** 找键，一秒后才按下 —— 窗口已闭，这一下的 6 只是切换快捷栏。

持续性的修饰键同样受此规矩：你若**已在疾奔**，SHIFT 便不曾被重新按下，因此 SHIFT 绑定不会触发，除非你停下再重新起步。这是刻意为之 —— 若改为读取「按住」状态，那么只要你还在疾奔，每一个绑定键都会被夺走。

两次触发之间另有 **600 毫秒**的防抖，因此手抖连按不会把灵气花两遍。

## 可绑定的内容

| 槽位 | 默认 | 绑定对象 |
| --- | --- | --- |
| **4 个功法绑定** | ALT+6、ALT+7、ALT+8、ALT+9 | 任何你能施展的[功法](/zh/techniques/) |
| **4 个菜单绑定** | ALT+3 → 灵气总览，ALT+4 → [典籍](/zh/codex/) | 任意修真菜单页 |
| **1 个配置组切换** | ALT+5 | 循环切换你的配置组 |

唯有你**确实绑定过**的组合才会被拦截。其余任何按键都照常行事，无论是否按着修饰键 —— 未绑定的 6 仍旧切换快捷栏，不加修饰键的 Q 仍旧丢出物品。

## 配置组

保存多套**具名配置组**，每套各有自己的四个功法绑定，一键循环切换。战斗一套、赶路一套，不必再手动重绑。

自 v0.7.0 起，默认保留**三套**配置组，快捷键页面会直白标出数量 —— `已存 2 / 3`。此上限并非配置项：扩展模组可通过 API（`registerTechniquePresetCap`）将其提高，硬性天花板为**八套**。若提高上限的扩展模组后来被移除，你已保存的每一套配置组**都会保留** —— 计数会转为金色以示你已超出上限，只是在回到上限以下之前，不能再*新建*而已。（在 v0.6.x 下保存过三套以上的玩家，也照样悉数保留。）

## 予服主

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `Technique-Hotkeys-Enabled` | true | 整套功能。关掉后功法仍可经 `/cultivation technique` 正常施展。 |
| `Technique-Hotkeys-Q-E-R-Enabled` | **false** | Q、E、R 是否可被绑定。 |

**Q、E、R 默认关闭。**它们是侵扰性较强的那一半：夺走其中任何一个，代价是玩家丢不了物品、开不了背包，或切不了快捷栏方块组 —— 而夺走一个带修饰键的数字键，代价仅仅是一次快捷栏切换，且模组会立刻把它还原。除非玩家主动要求，否则不必开启。

两者均位于 `Arts/TechniqueConfig.json`，参见[功法配置页](/zh/config-arts/)。

## 排查

绑定不触发，几乎总是以下三者之一：

1. **该键上什么都没绑。**尤其是 Q、E、R —— 它们默认既未绑定，也未启用。
2. **修饰键是按住而非按下。**见上文 —— 那是自按下起半秒的窗口。
3. **功法本身就过不去。**绑定绕不开境界要求、灵气消耗、冷却，或是你尚未研读的[秘籍](/zh/manuals/)。

`/cultivation debug hotkeys` 会开启服务端追踪并打印你当前的绑定，足以分辨「服务端压根没看到修饰键」与「看到了，但窗口已经闭上」。
