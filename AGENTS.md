# xianxia.dev — how to work in this repo

**This repo is one Next.js application, in `web/`. There is no other site.**

The wiki used to be zero-build static HTML generated by Python scripts, served by GitHub
Pages. That is gone — deleted 2026-08-04, after xianxia.dev moved to Vercel. If you are
looking for `convert_docs.py`, `enhance.py`, `en-src/`, `zh-src/`, `data/nav.js`,
`assets/js/site.js` or a directory full of `index.html` files, they existed until commit
`71478f6` and can be read out of git history or the `before-nextjs` branch. They are not
coming back.

## The rule

**Every change goes into `web/` as Next.js — MDX, React, or TypeScript. Never author an
HTML page, and never write anything with the intent of converting it to JSX later.**

Concretely, when asked to add something to the site:

| The ask | Where it goes |
| --- | --- |
| A new page, or new prose on an existing one | `web/content/en/<slug>.mdx` (+ `web/content/zh/<slug>.mdx`), and an entry in `web/lib/nav.ts` |
| A new visual element (callout, card, table treatment) | A React component in `web/components/mdx/`, then used in the MDX |
| Header, sidebar, TOC, footer, search | `web/components/chrome/` |
| Interactive behavior | A client component, or the ported logic in `web/lib/tools/` |
| Styling | `web/styles/next-overrides.css` — **not** `xianxia.css` |

Do not hand-write markup that duplicates what a component already renders. If a piece of
MDX starts needing raw `<div class="...">`, that is the signal to add a component instead.

## Chinese pages

`content/zh/` mirrors `content/en/` slug for slug. Chinese is a **first-class locale, not a
generated translation** — never machine-translate a technical page, and never invent a
config key name. Read the English page, translate from it, and check every `code span`
against the mod's own zh-CN pack:
`../Cultivation/src/main/resources/Server/Languages/zh-CN/server.lang`.

A page with no Chinese version simply has no `content/zh/` file and no `zhPage: true` in
`lib/nav.ts`; it links to the English page with an "EN" marker. That is a supported state,
not a bug to rush-fix.

## Read before editing

`web/README.md` covers the architecture: why there are two root layouts, the escaped-brace
MDX anchor rule, `/api/get/**` being a live endpoint deployed mods poll, and the tools in
`web/tools/`. `web/AGENTS.md` covers the Next.js version itself.
